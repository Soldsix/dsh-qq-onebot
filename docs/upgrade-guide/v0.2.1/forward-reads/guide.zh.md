# 升级范围绑定的转发读取

## 变更

完整 Config 对象新增 maxForwardNodes、maxForwardResources、maxForwardDepth 和 maxForwardCalls，原生所有者表单及控制响应包含这些字段。已保存 profile 未填写的字段由 schema 明确补默认值，不改变消息归档或会话格式。

Host 服务新增 readForward(scope, rootMessageId, resourceId, signal)，仅读取已接纳且仍保留的外层消息或已解析子节点引入的资源。返回的昵称和账号属于声称身份，不代表认证；只有引用 ID 的节点原样保留，不进行全局 get_msg 查询。缓存结果包含原始响应与范围绑定的附件引用，不代表已下载原始媒体字节。

## 迁移

1. 升级 bundle 并重新载入原生客户端，通过 Config 解析设置，或为手写完整设置添加四个字段。已有凭据引用、账号身份和会话允许名单仍适用。
2. 调用 readForward 时仅传入已认证的外层范围及原始消息 ID，显式处理失败；超限、格式错误或超时不能标为完成。供模型使用的材料由消费插件通过自己的会话事件记录。
3. 展示嵌套节点时保留原外层消息，不将节点作为新入站消息发布，不因声称发言者而授予管理权限。媒体按精确外层范围读取，原件下载和合并转发发送仍需要独立适配器。
4. 重新运行回环解析、取消、旧连接迟到响应和原生 profile 测试。本次不引入自动恢复、重试、归档改写或历史消息重放。
